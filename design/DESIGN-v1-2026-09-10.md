# abTEM benchmark suite: implementation plan

Date: 2026-09-10. Repo: `/workspaces/code/abTEM` (dev at 70e38e0f, v1.1.0). Author: Claude Code, for Paul.

Goal: run a fixed matrix of standard abTEM calculations (HAADF, diffraction, core-loss images, PRISM, frozen phonons, Bloch waves, ...) against two or more git refs and report, per case, (1) result accuracy and consistency, (2) speed, (3) peak memory.

## 0. Recommendation in one paragraph

Build a small self-contained harness under `benchmarks/abtem_bench/` with three strictly separated layers: declarative *cases* (what to compute), a subprocess-per-case *runner* with time and memory meters, and a *compare* tool that works on a commit-independent result format (NumPy `.npz` + JSON sidecars). Swap the library under test per ref with git worktrees plus `PYTHONPATH` (abtem is pure Python, verified below), with an isolated `uv venv` fallback for refs whose dependency pins differ. Do not adopt asv or pytest-benchmark (reasons in section 2). Consolidate the 13 ad hoc scripts already in `benchmarks/` into this harness and retire them.

## 1. What the repo already has, and what it dictates

- `benchmarks/` on dev holds 13 scripts (main has 1). Each re-implements the same pieces: per-config subprocess isolation, RSS and VRAM sampling threads, JSON output, and a side-by-side compare printer (`benchmark_comparison.py --compare`, `compare_benchmarks.py`). These are the prototype of exactly this suite; port `PeakRAMTracker`, `PeakVRAMTracker`, `_gpu_cleanup`, `_classify_subprocess_error` and the ▲/▼ table style, then delete the scripts.
- abtem is pure Python (no compiled extensions; numba and CuPy kernels JIT at runtime), so two refs can share one environment. Verified: `PYTHONPATH=<worktree> python -P -c "import abtem"` imports from the worktree even with the editable install active. The `-P` flag (or a cwd outside any checkout) is required: `python -c` run from the main checkout puts the cwd first on `sys.path`, which shadows `PYTHONPATH`.
- Dependency pins moved recently (numpy>=2 on 2026-01-30, zarr>=3.1 on 2026-07-03). Refs older than that may not import in today's env, so the runner needs an isolated-venv mode from the start if you want to compare against release tags such as v1.0.10.
- Several config keys silently change *results* or *timing* across commits and must be pinned by the suite: `grid.round-to-fast-fft` (since PR #347, gpts derived from `sampling` can change, so every case must pass explicit `gpts`); `precision`; `fft` and `fftw.planning_effort` (FFTW_MEASURE chooses plans by timing, so rounding can differ run to run); `fftw.threads`; `dask.lazy`; `dask.chunk-size` and `chunk-size-gpu`; `potential.slice-chunk-size: auto` and `max_batch="auto"` (both sized from *free* memory, so machine- and moment-dependent); `cupy.fft-cache-size`.
- GPU computes run on the synchronous dask scheduler (`abtem/array.py:_resolve_gpu_scheduler`); CPU computes use the threaded scheduler. Speed runs must pin `num_workers`, `OMP_NUM_THREADS`, `NUMBA_NUM_THREADS`, `fftw.threads`.
- The test suite already parametrises over `["cpu", gpu]` and uses rtol 1e-5 to 1e-6 and atol 1e-6 as its typical tolerances. `ArrayObject` exposes `.array`, `.axes_metadata`, `.metadata`, `.compute()`, `.to_cpu()`, which is a stable extraction surface across commits; do not rely on abtem's own zarr writer for stored results because it is itself subject to change.
- Tooling on the dev box: uv 0.12, psutil present, asv/pytest-benchmark/memray absent, GPAW 26.7.1b1 present (needed by `SubshellTransitions` for core-loss cases), ROCm GPU (`cp.cuda.Device().mem_info` works, pynvml does not).
- Core-loss entry point in current tests: `Probe.transition_potential_scan(potential=, transition_potentials=, scan=, detectors=)` with `SubshellTransitions(Z, n, l, xc, order, epsilon).get_transition_potentials(energy=)`.

## 2. Build vs adopt

| Option | Fits | Does not fit | Verdict |
|---|---|---|---|
| asv | Cross-commit `time_*`/`peakmem_*`, `asv continuous A B`, regression thresholds, machine fingerprint | No array-result comparison (only scalar `track_*`), no GPU memory, per-commit env management fights uv + ROCm CuPy, `--python=same` cannot compare two commits, low maintenance activity | Borrow its conventions (result naming, thresholds, fingerprint); do not adopt |
| pytest-benchmark | Timing statistics inside pytest | In-process only (no memory isolation), no cross-commit pairing, no arrays, no GPU | No |
| Existing scripts, extended | Proven subprocess isolation and meters | 13 copies of the same code, no shared result format, no accuracy layer | Port, then retire |
| Custom harness (~800 lines) | All three axes in one result format, ABAB interleaving, GPU-aware meters, `requires` guards for API drift | Must be written | Yes |

## 3. Architecture

### 3.1 Layers and the one rule

- `cases/`: declarative case definitions. Pure abtem API calls, no measurement code.
- `abtem_bench/`: registry, runner, worker, meters, store, compare, determinism presets, CLI.
- Rule: the harness and the cases are always taken from the *invoking* checkout; only `abtem` is swapped per ref. Both refs therefore run byte-identical case code. A case that needs an API absent on one ref declares `requires`, and that ref records status `UNSUPPORTED` instead of failing the run.

### 3.2 Case contract

A case is a function `(params, device) -> run`, where `setup` work happens in the function body (excluded from timing) and `run()` is a zero-argument callable that computes and returns abtem objects (timed). Registration is by decorator:

```python
@case(
    "stem.haadf",
    tags={"stem", "multislice"},
    tiers=dict(
        quick=dict(gpts=256, reps=(4, 4, 8), scan=(6, 6), max_batch=8),
        standard=dict(gpts=1024, reps=(8, 8, 15), scan=(16, 16), max_batch=8),
        large=dict(gpts=4096, reps=(20, 20, 75), scan=(8, 8), max_batch=8, devices=("gpu",)),
    ),
    variants=dict(eager=dict(lazy=False), auto_batch=dict(max_batch="auto")),
    tolerance=Tolerance(rtol=1e-5, atol_rel=1e-6),
)
def stem_haadf(params, device):
    atoms = bulk("Si", cubic=True) * params["reps"]
    potential = Potential(atoms, gpts=params["gpts"], slice_thickness=2.0, device=device)
    probe = Probe(energy=200e3, semiangle_cutoff=20, device=device)
    scan = GridScan(start=(0, 0), end=potential.extent, gpts=params["scan"])
    detectors = [AnnularDetector(inner=0, outer=30), AnnularDetector(inner=50, outer=180)]

    def run():
        return probe.scan(potential, scan=scan, detectors=detectors, lazy=params.get("lazy", True), max_batch=params["max_batch"]).compute()

    return run
```

Fields: `name`, `tags`, `tiers` (quick / standard / large; "standard" is the middle tier, never "production" or "default"), `variants` (parameter overrides that produce sibling case ids), `tolerance`, `requires` (callable feature guard, e.g. `hasattr(Probe, "transition_potential_scan")`), `outputs` (optional mapper from the run result to `{name: ArrayObject}`; default handles a single object, a list, or a dict), `nominal_bytes` (optional; size of potential + wave batch, for a memory-overhead ratio), `consistency` (pairs of variants or devices whose outputs must agree, with their own tolerance), `seed` for stochastic cases.

Case id: `name[variant]@tier/device`, for example `stem.haadf[eager]@quick/gpu`.

### 3.3 Result contract (commit-independent, schema-versioned)

```
results/<run-id>/
  manifest.json              # schema_version, ref, sha, dirty flag, abtem version, env fingerprint, preset, tier, device, timestamp
  cases/<case-id>.json       # status, timings, memory, outputs index, error text
  cases/<case-id>/<output>.npz
```

- Per output: array in native dtype (CuPy moved to host; complex kept complex), `shape`, `dtype`, `axes` as a list of `{type, label, units, sampling, offset, values}`, a JSON-safe subset of `metadata`, and invariants (`sum`, `mean`, `min`, `max`, `abs_max`).
- Timings: `cold` (first call: numba JIT, FFTW planning, CuPy kernel compilation), `repeats` (list), `median`, `min`, `cpu_time`, and `setup` (informational).
- Memory: `peak_rss_mb` (sampler), `maxrss_mb` (`ru_maxrss` cross-check), `peak_vram_pool_mb` (CuPy mempool `used_bytes`), `peak_vram_device_mb` (driver-level `total - free`, which also captures cuFFT workspace outside the pool), `nominal_mb` when declared.
- Status: `OK`, `UNSUPPORTED`, `ERROR`, `OOM`, `TIMEOUT`.
- Env fingerprint: python, numpy, scipy, dask, pyfftw, numba, cupy, gpaw versions; CPU model and core count; GPU name and driver; thread env vars; the full abtem config snapshot; `git describe`.
- Backward compatibility: `schema_version` in the manifest, additive changes only, and the compare tool must keep reading every earlier schema.

### 3.4 Runner and environment

- `run --ref A --ref B`: for each ref, `git worktree add .worktrees/bench/<sha>` (add `.worktrees/` to `.gitignore`; it is currently untracked but not ignored).
- Shared mode (default): one subprocess per case id per ref, `python -P -m abtem_bench.worker ...` with `PYTHONPATH=<worktree>` and cwd set to the results dir.
- Isolated mode (`--isolated`): `uv venv .worktrees/bench/<sha>/.venv` and `uv pip install -e <worktree> --constraint <freeze of the invoking env>`, so only abtem differs. Required for refs across the numpy 2 / zarr 3.1 pin changes.
- Order: interleave refs per case (A case1, B case1, A case2, ...) so thermal and background drift hits both refs alike; `--rounds N` repeats the whole matrix to expose drift.
- Isolation is what makes memory peaks clean and lets OOM or hangs kill one case rather than the run. Per-tier timeouts (quick 120 s, standard 900 s, large none) map to `TIMEOUT`; stderr classification (ported from `benchmark_potential_chunking.py`) maps CUDA and cgroup kills to `OOM`.
- `--self-check` runs the same ref twice (A vs A) to measure the noise floor for accuracy (should be bitwise identical on CPU under the accuracy preset) and for time (spread of medians). The compare tool uses that floor for its flags.

### 3.5 Meters (in the worker)

- Wall time with `perf_counter`, GPU synchronised before stop; process CPU time alongside, so the utilisation ratio is visible.
- Warm-up run recorded as `cold`, then N repeats (default 5, 1 for `large`), CuPy pools freed between repeats.
- Peak RSS sampler thread (50 ms) plus `ru_maxrss`; optional `--tracemalloc` for Python-heap attribution (off by default, it slows runs).
- Peak VRAM sampler thread (5 ms) recording both mempool `used_bytes` and device-level `total - free`.

### 3.6 Compare and report

- Pairing by case id; unmatched ids reported as "A only" / "B only".
- Accuracy per output: `identical` (bitwise), `max_abs`, `max_rel` (denominator `max(|ref|, atol_rel * abs_max)`), `rel_l2`, invariant deltas, exact match of shape and axes (sampling, offset, units). Verdicts: `IDENTICAL`, `OK` (within tolerance), `DRIFT` (beyond tolerance, same shape), `SHAPE` (shape or axes changed), plus the run statuses.
- Consistency: within one run, declared pairs (cpu vs gpu, lazy vs eager, `max_batch` 1 vs 8, PRISM vs multislice, float32 vs float64) are compared with the pair's tolerance; the report also shows whether a consistency gap widened between refs.
- Speed: ratio of medians B/A (min-of-N as a robustness check); flagged when `|ratio - 1|` exceeds `max(threshold, 3 × noise floor)` (default threshold 10 %). Cold-start ratio reported separately, since JIT and planning regressions are user-visible too.
- Memory: ratios on peak RSS and VRAM; flagged above 5 % in pinned variants; `auto_batch` variants are reported but never flagged, because auto-sizing legitimately depends on free memory.
- Outputs: Markdown table (mirrors the existing ▲ ▼ ≈ style), `compare.json`, and an exit code (`--fail-on accuracy`, `--fail-on speed:10%`, `--fail-on memory:5%`) for CI.

### 3.7 CLI

```
python -m abtem_bench list [--tag stem] [--tier quick]
python -m abtem_bench run --ref dev --ref v1.0.10 --device cpu,gpu --tier quick --preset speed --out results/
python -m abtem_bench run --self-check --ref dev --tier quick
python -m abtem_bench compare results/<A> results/<B> [--md report.md] [--json] [--fail-on accuracy]
```

## 5. Determinism presets

- `accuracy`: `fft: fftw` with `FFTW_ESTIMATE` (plan chosen by heuristic, not timing), `fftw.threads: 1`, `num_workers: 1`, `precision` per case (float32 default, float64 variants on a few cases), explicit `gpts`, explicit `max_batch` and `potential_chunk_size`, fixed seeds, `TQDM_DISABLE=1`, progress bars off.
- `speed`: user-default FFTW settings, but thread counts and `num_workers` fixed and recorded; pinned batch and chunk sizes; the `auto_batch` variant is included for memory.
- `memory`: as `speed`, 1 repeat, finer sampler intervals.
- One run records all three axes; the preset only changes config. Recommended workflow: `--preset accuracy --tier quick --device cpu` for the correctness gate, `--preset speed --tier standard` for performance.

## 6. Repo layout and packaging

```
benchmarks/
  README.md
  bench.py                 # thin shim: adds benchmarks/ to sys.path, runs abtem_bench.cli
  abtem_bench/
    __init__.py
    cli.py                 # list / run / compare
    registry.py            # @case, Case, Tolerance, tiers, tags
    runner.py              # worktrees, envs, subprocess orchestration, interleaving, timeouts
    worker.py              # one case in one subprocess: setup -> cold -> repeats -> meters -> store
    meters.py              # WallClock, PeakRSS, PeakVRAM (ported and extended)
    store.py               # schema, npz + json, fingerprint
    compare.py             # pairing, metrics, verdicts, markdown/json rendering
    determinism.py         # presets
  cases/
    potentials.py hrtem.py diffraction.py stem.py prism.py phonons.py coreloss.py bloch.py
  results/                 # gitignored
```

- Nothing ships in the wheel: add `[tool.setuptools.packages.find] exclude = ["benchmarks*", "test*"]` and no console script in `pyproject.toml`.
- No new hard dependencies: numpy, `tabulate` (already required), psutil (present; optional).
- Legacy scripts: move to `benchmarks/legacy/` in M1 and delete in M4 once every measurement they made has a case.

## 7. Where it runs

- Accuracy gate in CI: new workflow `benchmark-accuracy.yml` on `workflow_dispatch` and PR label `benchmark`; ubuntu, Python 3.12, `uv sync --group test`; quick tier, CPU, accuracy preset, PR head vs merge-base with dev; report to `$GITHUB_STEP_SUMMARY`; fail on `DRIFT` or `SHAPE` unless the PR carries `benchmark-accept`.
- Speed and memory never on hosted runners (too noisy). Run on the dev box (24 cores, 46 GB, ROCm GPU) and on Delta via the same CLI inside the existing containers; results dir is a run artifact, not committed.
- No golden result files in git: worktrees make re-running an old ref cheap, and `.npz` files would bloat the repo. If a release baseline is wanted, attach the results directory to the GitHub release.
